# Release v1.1.6 Multi-Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release AetherGrok Desktop Studio v1.1.6 containing token truncation guards, auto-retry recovery, strict session isolation, continuation hardening, and session deduplication, trigger GitHub Actions multi-platform builds for Windows and macOS, and monitor until all build jobs succeed and release assets are published without error.

**Architecture:** 
1. Pre-flight & Versioning: Bump application semantic version to `1.1.6` across `wails.json` and `frontend/package.json`. Rebuild frontend production bundle (`frontend/dist/`) and verify all backend Go tests and frontend Vitest suites pass cleanly.
2. Git Tagging & Dispatch: Commit all changes, create git tag `v1.1.6`, and push `main` along with the tag to remote repository `origin` (`fiko942/aethergrok`).
3. GitHub Actions CI/CD Monitoring: Track GitHub Actions workflow `Release Multi-Platform AetherGrok Desktop Studio` (`release.yml`), monitoring both Windows matrices (`amd64`, `arm64`), macOS matrices (`amd64`, `arm64`, `universal`), and release packaging job until 100% completion with 0 errors.

**Tech Stack:** GitHub Actions, Wails v2, Go 1.24+, Svelte 5, Node 20+, GitHub CLI (`gh`).

## Global Constraints

- Do not push a broken build: all Go tests (`go test ./pkg/...`) and frontend build must pass locally before pushing.
- Version numbers in `wails.json` (`productVersion`, `version`) and `frontend/package.json` (`version`) must match `1.1.6`.
- Tag name must follow standard format `v1.1.6`.
- Monitor GitHub Actions until all jobs (`build-windows`, `build-macos`, `release`) complete with status `success`.
- Any GitHub Actions failure must be inspected immediately via `gh run view --log-failed`.

**Interfaces:**
- Consumes: Tag push `v1.1.6`
- Produces: GitHub Release `v1.1.6` with Windows & macOS binary assets

- [ ] **Step 1: Locate the triggered GitHub Actions workflow run**

Run: `gh run list --workflow=release.yml --limit 3`
Find the Run ID associated with tag `v1.1.6`.

- [ ] **Step 2: Monitor GitHub Actions run until completion**

- `build-windows (amd64)`

- `build-macos (macos-latest - arm64)`
- `build-macos (macos-latest - amd64)`

- `release`

- [ ] **Step 3: Verify all jobs completed successfully**

Run: `gh release view v1.1.6`
Verify presence of:
- Windows installer & portable zip (`.exe`, `.zip`)
- macOS DMG & app zip (`.dmg`, `.zip`)
- Checksum files (`.sha256`)
